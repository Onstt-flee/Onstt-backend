# 일본어 판단 평가셋 경계 기준

상태: v0.1 익명 사용자 검수 완료. 검수일: 2026-09-04. 적용 문항: `JG-061`–`JG-072`.

이 문서는 필러, 문체, STT 전사 표기, 대화 문맥을 문법 오류와 섞지 않기 위한 검수 기준이다.
기존 문법 판단 상태는 `acceptable / needs_correction / insufficient_evidence` 세 가지로 유지한다.
아래 보조 항목은 정답 쪽 `tags`에 `check:` 접두어로 기록하며, 현재 모델 출력 필드나 자동 판정 결과가 아니다.

## 한 줄 기준

| 항목 | 기준 |
| --- | --- |
| 필러·간투어 | 문장에 포함된 필러는 유지하고 명확한 문법 오류만 고친다. 필러뿐이라 판단할 내용이 없으면 보류한다. |
| 문체 혼용 | 혼용만으로 문법 오류를 만들지 않는다. 명시적인 문체 요구와의 불일치는 별도 문체 제안으로 기록한다. |
| 발음·표기·전사 | 표기 정규화 후보와 전사상의 문법 오류를 분리하며, 원음 없이 학습자의 실수인지 STT 오류인지 확정하지 않는다. |
| 동문서답 | 문법 판단과 질문 관련성을 분리한다. 질문에 맞추려고 사용자가 말하지 않은 내용을 생성하지 않는다. |

`acceptable`은 **문법 구조를 고칠 필요가 없다**는 뜻이다.
표기·문체·질문 적합성·발음까지 모두 정상이라는 의미로 사용하지 않는다.
보조 태그가 없는 기존 문항은 해당 차원을 검토하지 않은 것으로 본다.

## 1. 필러와 의미 있는 표현

- `JG-061` `あのう、来週は大阪に行きます。`: 문법상 허용하고 `あのう`를 유지한다.
- `JG-062` `ええと、昨日は駅で友達に会うました。`: `会うました`만 `会いました`로 고치고 `ええと`는 유지한다.
- `JG-063` `なんか飲む？`: 음료를 권하는 문맥에서 `なんか`는 마실 무언가를 가리키므로 삭제하지 않는다.
- 기존 `JG-051`처럼 머뭇거림만 있고 판단할 문장 내용이 없으면 `insufficient_evidence`다.

모든 `なんか`를 필러 또는 의미 표현으로 일괄 분류하지 않는다. 문장 안의 역할과 문맥을 확인한다.
가독성용 필러 제거가 필요하면 원문·문법 교정문과 구분된 후처리로 제공한다.

## 2. 문체 혼용

- `JG-064`: `昨日は図書館に行きました。そして本を読んだ。`가 친한 친구와의 대화이고 문체 요구가 없으면 문법상 허용한다.
- `JG-065`: 같은 문장이라도 면접 연습에서 모든 독립 문장을 です・ます체로 통일하라는 지시가 있으면 문법 판단은 유지하고 `本を読みました`를 별도 문체 제안으로 표시한다.
- `JG-066` `明日は雨が降ると思います。`: 생각의 내용인 `降る`와 주절의 `思います`는 정상 연결이다. `降りますと思います`로 고치지 않는다.

직접 인용, 종속절, 담화 효과가 있는 문체 전환을 단순 혼용으로 세지 않는다.
격식체가 필요하다는 문맥이 없으면 문체 통일을 강제하지 않는다.

## 3. 발음·표기·STT 전사

- `JG-067` `わたしわ大学生です。`: 문법 구조는 허용하되 `わたしは大学生です。`를 표기 정규화 후보로 표시한다.
- `JG-068` `本お読みます。`: 문법 구조는 허용하되 `本を読みます。`를 표기 정규화 후보로 표시한다.
- 두 문항 모두 원음·대안 전사가 없으므로 학습자가 잘못 발음했는지 STT가 잘못 옮겼는지 단정하지 않는다.
- `JG-069` `毎朝、バスで大学を行きます。`: 목적지가 대학이라는 문맥이 있으므로 전사 텍스트의 `を`는 `に` 또는 `へ`로 문법 교정한다. 원인은 여전히 미확인이다.

`JG-067`·`068`의 `corrected_text`가 원문인 이유는 현재 계약이 문법 교정 전용이기 때문이다.
이는 원문 표기가 올바르거나 발음이 정확하다는 인증이 아니다. 운영 UI에서 `acceptable`만 보고 전체 발화를 정상 승인해서는 안 된다.
표기 정규화, 가독성 편집, 문체 통일을 현재 문법 교정문에 섞지 않는다.

이 정책은 문법 구조가 명확한 제한된 표기 차이 사례에 적용한다.
전사 누락·중의성 때문에 문법 구조나 의도를 알 수 없다면 `insufficient_evidence`를 사용한다.
쓰기 평가를 추가할 때에는 표기 정확도를 별도 목표와 시험지로 정의한다.

## 4. 질문과 답변의 관련성

- `JG-070`: “어제 무엇을 했나요?”에 대한 `りんごが一番好きです。`는 문법상 허용이지만 질문과 불일치한다.
- `JG-071`: “어떤 과일을 가장 좋아하나요?”에 같은 답을 했다면 문법과 문맥 모두 맞는다.
- `JG-072`: “어제 무엇을 했나요?”에 `りんごが一番好きだです。`라고 하면 `好きだです`를 `好きです`로 고치면서 문맥 불일치도 함께 기록한다.

동문서답을 네 번째 단일 문법 상태로 만들지 않는다. 문법 오류와 문맥 불일치는 동시에 존재할 수 있기 때문이다.
문맥 정보가 없으면 동문서답이라고 단정하지 않으며, 질문에 맞는 답을 임의로 생성해 교정문으로 대체하지 않는다.

## 저장 및 구현 경계

현재 보조 태그:

- `check:filler_preserve`
- `check:lexical_content_preserve`
- `check:style_preserve`
- `check:style_advisory`
- `check:orthography_candidate`
- `check:attribution_unknown`
- `check:context_match`
- `check:context_mismatch`

검증기는 알려지지 않은 `check:` 태그와 문법 출력의 임의 필드 추가를 거부한다.
모델 입력 내보내기에는 정답 태그가 포함되지 않는다.
`context_fit` 같은 모델 출력, 자동 문체·표기 검사, 발음 판정, 튜터의 재질문 기능은 아직 구현하지 않았다.
초기 60개와 보강 12개의 결과는 따로 보고해 시험지 구성이 달라진 효과를 구분한다.
