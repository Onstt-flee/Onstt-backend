# 사람 검수 자료

이 폴더에는 `seed_v0.1.jsonl`의 익명 사용자 검수를 완료한 72개 합성 문항 배포 자료가 들어간다.

- `judgment_review_sheet_v0.1.xlsx`: 익명 검수 결과와 72문항 최종 피드백을 취합한 Excel 파일
- `judgment_review_packet_v0.1.pdf`: 초안 정답을 가린 인쇄·배포용 PDF
- `../complete_mapping_v0.1.json`: 완전 문장 번호 1~27과 평가셋 ID 매칭 원본
- `../feedback_mapping_v0.1.json`: 교정 피드백 번호 1~30과 평가셋 ID 매칭 원본
- `../ambiguous_mapping_v0.1.json`: 애매 문장 번호 1~14와 평가셋 ID 매칭 원본

## 현재 매칭 결과

- 완전 문장 27개 번호 → 평가셋 27문항
- 교정 피드백 30개 번호 → 문맥 중복을 포함한 평가셋 31문항
- 애매 문장 14개 번호 → 문맥 중복을 포함한 평가셋 15문항
- 세 목록의 합집합 → 비어 있지 않은 평가셋 **71/71문항**
- `JG-049`는 원문이 빈 문자열이므로 외부 문장 번호와 매칭하지 않고 `전체매칭_현황`에 별도 기록

두 외부 목록에 같은 문체 혼용 문장이 있어 `JG-064`, `JG-065`는 복수 목록에 나타난다.
완전 문장 목록의 25번과 27번은 `りんごが一番好きです。`로 동일하다.
25번은 문법은 완전하지만 질문과 맞지 않는 `JG-070`, 27번은 질문에도 맞는 `JG-071`로 문맥 기준 배정했다.

## 권장 사용 순서

1. `최종피드백_요약`에서 72문항의 판단·교정·객관 근거·학습자 피드백·신뢰도를 한 번에 확인한다.
2. `2차_대조검수`에서 현재 72문항이 승인되고 확정 판단·교정문·검수일이 기록됐는지 확인한다.
3. `완전문장_매칭`, `교정피드백_매칭`, `애매문장_매칭`에서 외부 번호와 JG ID를 확인한다.
4. `전체매칭_현황`에서 비어 있지 않은 71문항의 커버리지와 JG-049 빈 입력을 확인한다.
5. 독립 재검수가 필요할 때만 PDF 또는 `1차_블라인드`를 사용한다. 개인 검수자 식별자는 기록하지 않는다.

애매 문장의 누락 부분을 채운 문장은 실제 발화를 복원한 정답이 아니다.
대화 복구 문구, 문장 완성 연습 예시, 번역 예시 또는 문체 대안으로 분리한다.
침묵의 의도를 `잘 모르겠다`로 단정하거나 전사 공백을 `学校`·`寒`으로 자동 복원하지 않는다.

PDF는 **독립 블라인드 재검수본**이므로 확정 판단·교정문·매칭표를 넣지 않는다.
필기본은 증빙과 공유에 사용하고, 구조화된 최종 취합은 Excel 파일을 기준으로 한다.

## 다시 생성하기

저장소 루트에서 실행한다.

```bash
venv/bin/pip install -r evaluation/judgment/review-requirements.txt
venv/bin/python -B -m evaluation.judgment.generate_review_materials \
  --font-path /path/to/NotoSansKR.ttf \
  --japanese-font-path /path/to/NotoSansJP.ttf
```

지역별 CJK 글꼴은 서로 일부 글리프가 빠질 수 있으므로 한글용·일본어용 글꼴을 각각 지정한다.
지정하지 않으면 시스템 글꼴을 찾고, 없으면 PDF 뷰어의 CJK 글꼴 대체 기능을 사용한다.
현재 서버에는 Noto Sans KR/JP 글꼴 파일이 없어 저장된 PDF는
`HYSMyeongJo-Medium`과 `HeiseiMin-W3` CID 대체 글꼴을 사용한다.
공유 전 대상 PDF 뷰어에서 한글·일본어 표시를 확인하고, 독립 글꼴 포함이
필요하면 `--font-path`와 `--japanese-font-path`로 Noto 글꼴을 지정해 다시 생성한다.

생성 결과는 검수 편의용 파생 파일이다. 정답의 기준 원본은 항상 `../seed_v0.1.jsonl`이다.
