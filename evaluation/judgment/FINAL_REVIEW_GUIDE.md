# 일본어 판단 평가셋 최종 재검수 가이드

기준일: 2026-09-04

대상 데이터: `seed_v0.1.jsonl` 72문항
상태: 익명 사용자 검수 완료·평가셋 반영 완료 (`user_reviewed`, 2026-09-04)

## 1. 문서 목적

이 문서는 일본어 문법 판단모델의 최소 평가셋에 적용한 2차 대조검수 기준과 확정 결과를 한곳에 정리한다.

검수자는 문법 오류, 문체·격식, 표기, 발음, STT 전사, 문장 완결성, 질문 관련성을 서로 다른 판단축으로 다룬다. 더 자연스러운 표현이 있다는 이유만으로 올바른 문장을 교정하지 않으며, 누락된 발화를 추측해 정답을 만들지 않는다.

현재 72문항은 익명 사용자 검수 완료본이다. 다음 경계는 계속 지킨다.

- 현재 모델 출력 계약에 새 필드를 임의로 추가하지 않는다.
- 사용자 검수를 일본어 전문가 인증으로 표시하지 않는다.
- 이 소규모 합성 진단셋의 점수를 운영 품질로 일반화하지 않는다.
- 평가 문항을 학습 데이터·few-shot·RAG 문서로 사용하지 않는다.

## 2. 현재 상태와 신뢰도 해석

외부에서 제공된 세 목록과 평가셋의 현재 매칭 상태는 다음과 같다.

| 항목 | 결과 | 해석 |
| --- | ---: | --- |
| 비어 있지 않은 평가 문항 | 71개 | `JG-049`의 빈 입력은 별도 관리 |
| 외부 문장과 원문 완전 일치 | 70/71, 98.6% | 매칭 신뢰도 높음 |
| 현재 초안과 외부 분류의 일치 | 65/71, 91.5% | 잠정 교차 일치도이며 정확도가 아님 |
| 완전 문장 보존 | 27/27, 100% | 문법 판단 기준의 일치도가 높음 |
| 교정문 완전 일치 | 26/30, 86.7% | 문체·표기 범위 충돌을 별도 확인해야 함 |
| 익명 사용자 2차 검수 결과 | 72/72 | 전 문항 `user_reviewed`; 전문가 인증은 아님 |

교정 목록 19번은 외부 원문의 `昨日のお昼ごはん`과 평가셋의 `昨日の昼ごはん`이 다르다. 핵심 시제 교정 `食べます → 食べました`는 일치한다.

위 비율은 자료 간 **일치도**다. 전문가가 정답을 인증했다는 뜻이 아니며 모델 정확도로 보고해서는 안 된다.

## 3. 정답 원본과 매칭 원칙

정답의 기준 원본은 `seed_v0.1.jsonl`이다. Excel, PDF, Markdown 표는 검수 편의를 위한 파생 자료다.

검수할 때 다음 순서를 지킨다.

1. 평가셋 `ID`를 확인한다.
2. 원문을 글자 단위로 확인한다.
3. `context`와 `learner_level`을 함께 읽는다.
4. 문법 판단과 부가 판단을 분리한다.
5. 교정문이 필요한 경우에만 최소 교정을 작성한다.

외부 자료의 1번, 2번 같은 번호는 시트나 평가셋 번호와 같지 않다. 외부 번호만 보고 판정을 복사하지 않는다.

동일한 원문도 문맥에 따라 서로 다른 평가셋 문항이 될 수 있다.

| 원문 | ID | 문맥 | 처리 |
| --- | --- | --- | --- |
| `昨日は図書館に行きました。そして本を読んだ。` | JG-064 | 친한 친구와의 대화, 문체 요구 없음 | 문법상 허용 |
| 같은 원문 | JG-065 | 면접에서 です・ます체 통일 요구 | 문법상 허용＋문체 조언 |
| `りんごが一番好きです。` | JG-070 | 어제 한 일을 묻는 질문 | 문법상 허용＋문맥 불일치 |
| 같은 원문 | JG-071 | 좋아하는 과일을 묻는 질문 | 문법·문맥 모두 허용 |

원문은 표시용으로 임의 정규화하지 않는다.

- `明日は［聞き取れない］に行きます。`의 누락 표시를 `［ ］`로 바꾸지 않는다.
- `今日は［聞き取れない］かったです。`의 누락 표시를 삭제하지 않는다.
- `I went to the station yesterday.`를 말줄임표로 축약하지 않는다.
- 공백, 구두점, 전각 기호도 원본과 비교한다.

## 4. 최종 판단축

### 4.1 현재 문법 판단 상태

현재 문법 판단 상태는 세 가지로 유지한다.

| 상태 | 기준 |
| --- | --- |
| `acceptable` | 주어진 텍스트의 문법 구조를 반드시 수정할 필요가 없음 |
| `needs_correction` | 근거가 명확한 문법 오류가 있고 최소 교정이 가능함 |
| `insufficient_evidence` | 빈 입력, 누락, 잡음, 범위 밖 입력 등으로 문법 판단 근거가 부족함 |

`acceptable`은 표기, 발음, 문체, 자연스러움, 질문 관련성까지 모두 통과했다는 뜻이 아니다.

### 4.2 부가 판단축

문법 외 문제는 문법 상태와 분리한다.

| 부가 판단 | 의미 |
| --- | --- |
| `style_advisory` | 문체·격식·일관성에 대한 선택적 개선 제안 |
| `orthography_advisory` | 가나·조사 등 표기 정규화 제안 |
| `pronunciation_review` | 실제 음성이 있어야 확인할 수 있는 발음 검토 |
| `context_mismatch` | 문법은 성립하지만 질문이나 상황과 내용이 맞지 않음 |
| `unsupported_language` | 현재 일본어 문법 판단 범위 밖의 언어 입력 |
| `conversation_recovery` | 다시 말하기, 생각할 시간 요청 등 대화 복구 안내 |
| `translation_example` | 타 언어 입력의 참고 번역이며 교정 정답이 아님 |

현재 v0.1 모델 출력 계약은 다음 네 필드뿐이다.

- `decision`
- `corrected_text`
- `edits`
- `reason_ko`

부가 판단은 현재 평가셋의 `check:` 태그와 검수 의견으로 관리한다. `advisories` 등의 새 모델 출력 필드는 이번 사람 검수 결과가 확정된 뒤 별도 버전에서 설계한다.

## 5. 공통 검수 기준

### 5.1 최소 교정과 의미 보존

- 문법적으로 반드시 필요한 부분만 고친다.
- 원문의 의미, 시제, 긍정·부정, 말투와 필러를 보존한다.
- 더 세련된 문장으로 재작성하는 것과 문법 교정을 구분한다.
- 둘 이상의 올바른 교정이 있으면 허용 후보로 기록한다.
- 존재하지 않는 장소, 동작, 이유, 감정이나 의도를 추가하지 않는다.

### 5.2 필러와 회화체

- 완성된 문장 속 `あのう`, `ええと`는 기본적으로 보존한다.
- 필러만 있고 판단할 명제가 없으면 `insufficient_evidence`다.
- 필러 반복은 문법 오류가 아니라 유창성 조언 대상이다.
- `あのう`를 `実は`로 바꾸면 의미가 달라지므로 교정문으로 사용하지 않는다.
- `なんか飲む？`처럼 문맥상 의미가 있는 구어 표현을 의미 없는 필러로 삭제하지 않는다.

### 5.3 문체와 격식

- 정중체와 보통체의 혼용만으로 문법 오류를 만들지 않는다.
- 각 절이 문법적으로 성립하는지와 문체가 일관적인지를 분리한다.
- 면접·발표 등 문체 조건이 명시된 경우 `style_advisory`를 기록한다.
- 더 정중한 표현이 있다는 이유만으로 캐주얼한 원문을 오답 처리하지 않는다.

### 5.4 표기·발음·STT

- 쓰기 평가에서는 `わ → は`, `お → を` 같은 표기 오류를 교정할 수 있다.
- STT 문법 평가에서는 원음 없이 학습자의 발음 오류와 전사 오류를 구분할 수 없다.
- 문법 구조, 표기 정확성, 발음 정확성을 하나의 상태로 합치지 않는다.
- 원음이 없으면 발음 오류를 단정하지 않고 `pronunciation_review`로 남긴다.

예시:

```text
grammar_decision: acceptable
orthography_decision: needs_correction
pronunciation_decision: insufficient_evidence
```

### 5.5 미완성·잡음·타 언어

- 녹음 중단이나 전사 누락 뒤의 내용을 추측하지 않는다.
- 가능한 완성문은 학습 예시일 뿐 `corrected_text`가 아니다.
- 잡음만 있으면 판단할 일본어 발화가 없는 것으로 처리한다.
- 영어·한국어 입력은 번역할 수 있지만 문법 교정 정답으로 저장하지 않는다.

### 5.6 질문과 답변의 관련성

- 문법 판단과 질문 관련성을 별도로 판단한다.
- 동문서답을 고치기 위해 사용자가 말하지 않은 답을 생성하지 않는다.
- 문법 오류와 문맥 불일치는 동시에 존재할 수 있다.
- 문맥이 제공되지 않았다면 질문 불일치를 추측하지 않는다.

### 5.7 설명 품질

- `reason_ko`는 실제 판단과 교정에 직접 대응해야 한다.
- “항상”, “무조건”, “완벽”, “반드시” 같은 절대 표현을 신중히 사용한다.
- 확인되지 않은 발음, 의도, 능력이나 오류 원인을 단정하지 않는다.
- 학습자용 친절한 피드백과 평가 정답의 객관적 근거를 구분한다.

## 7. 판단 불충분·범위 밖 문항

다음 문항은 누락 내용을 임의 생성하지 않는다. `corrected_text`는 원문 유지 또는 비어 있는 정책값을 따르고, 제안 문구는 대화 복구·학습 예시·번역 예시로만 관리한다.

| ID | 원문 | 최종 판단 | 처리 및 주의점 |
| --- | --- | --- | --- |
| JG-049 | 빈 문자열 | `insufficient_evidence` | 판단할 입력 없음 |
| JG-050 | `……` | `insufficient_evidence` | 침묵을 “잘 모르겠다”는 의도로 해석하지 않음 |
| JG-051 | `あの、ええと……` | `insufficient_evidence` | 필러만 있고 판단할 명제 없음 |
| JG-052 | `昨日、駅で友達に` | `insufficient_evidence` | `会いました` 등 서술어를 임의 생성하지 않음 |
| JG-053 | `もし明日雨が降ったら` | `insufficient_evidence` | 결과절을 `家にいます` 등으로 임의 생성하지 않음 |
| JG-054 | `この本を読んだのは` | `insufficient_evidence` | 시간·사람·이유 중 무엇이 이어질지 알 수 없음 |
| JG-055 | `私は昨日、病院に……` | `insufficient_evidence` | `行きました`가 유력해도 확정하지 않음 |
| JG-056 | `明日は［聞き取れない］に行きます。` | `insufficient_evidence` | 목적지를 `学校` 등으로 채우지 않음 |
| JG-057 | `［雑音］` | `insufficient_evidence` | 다시 말해 달라는 문장은 시스템 복구 응답으로만 사용 |
| JG-058 | `今日は［聞き取れない］かったです。` | `insufficient_evidence` | 형용사 어간을 `寒` 등으로 채우지 않음 |
| JG-059 | `I went to the station yesterday.` | `insufficient_evidence` | `unsupported_language`; 일본어 문장은 번역 예시로만 관리 |
| JG-060 | `내일 학교에 갑니다.` | `insufficient_evidence` | `unsupported_language`; 일본어 문장은 번역 예시로만 관리 |

대화 복구 예시는 사용할 수 있지만 골드 교정문과 분리한다.

- `少し考えさせてください。`
- `すみません、もう一度話してください。`
- `すみません、よくわかりません。`

이 문장들은 유용한 대화 전략이지만 누락된 원문의 복원 정답은 아니다.

JG-065에 제시할 수 있는 문체 대안:

- 최소 문체 수정: `昨日は図書館に行きました。そして本を読みました。`
- 자연스러운 재작성: `昨日は図書館に行って、本を読みました。`

두 번째 문장은 연결 구조까지 바꾼 재작성이다. 유일한 골드 교정으로 강제하지 않는다.

## 9. 문법상 허용 문장의 설명 보완

다음 문장은 문법 판단보다 기존 설명의 정확성을 다시 확인해야 한다.

| ID | 원문 | 최종 설명 기준 |
| --- | --- | --- |
| JG-004 | `今日はあめです。` | 문맥·음성이 없으면 `雨`와 `飴`를 확정하지 않는다. 날씨 문맥이 명시되면 `雨`를 제안할 수 있으며 히라가나 자체는 허용된다. |
| JG-012 | `田中さんは来ないと思います。` | `と思います` 앞의 인용 내용은 기본적으로 보통형이다. 여기서 보통형은 청자에게 반말한다는 뜻이 아니라 문장 내부의 접속 형식이다. |
| JG-014 | `この町は静かで、住みやすいです。` | `住みやすい`는 `동사 ます형 어간＋やすい` 구조로 설명한다. |
| JG-016 | `母が作ったカレーを食べました。` | 이 문장에서는 수식절의 `が`가 자연스럽다. 모든 명사 수식절에 `が`만 가능하다고 일반화하지 않는다. |
| JG-017 | `この計画には再検討が必要です。` | 이 문장에서는 `再検討が必要`가 맞다. `必要` 앞에는 언제나 `が`만 온다고 설명하지 않는다. |
| JG-019 | `まだです。` | 앞선 질문에서 생략된 동작이나 상태가 아직 완료되지 않았다는 응답이다. 구체적 의미는 문맥에 따라 달라진다. `まだ未定でございます`와 같은 뜻이 아니다. |
| JG-022 | `水は飲まなくてもいいです。` | 마실 의무가 없다는 뜻이다. 물을 사양하는 `お水は結構です`와 동일한 표현으로 취급하지 않는다. |
| JG-070 | `りんごが一番好きです。` | 문법은 허용되지만 어제 한 일을 묻는 질문과 맞지 않는다. `context_mismatch`를 별도로 기록한다. |
| JG-071 | 같은 원문 | 좋아하는 과일을 묻는 질문에는 문법·내용 모두 맞는다. JG-070의 판정을 복사하지 않는다. |

검수 문서의 제목과 설명에서는 “완벽한 문장”보다 “문법상 허용 문장”을 사용한다. 문법상 허용과 문맥·표기·발음의 적합성이 다르기 때문이다.

## 10. 교정문·조언문·복구문 저장 경계

다음 세 종류를 하나의 `corrected_text`에 섞지 않는다.

1. 문법 오류를 고친 골드 교정문
2. 더 정중하거나 자연스러운 스타일 대안
3. 누락·잡음 상황에서 사용할 대화 복구 문장

현재 계약에서의 원칙:

| 상황 | `decision` | `corrected_text` | 별도 기록 |
| --- | --- | --- | --- |
| 명확한 문법 오류 | `needs_correction` | 최소 교정문 | 복수 허용 교정은 `accepted_corrections` |
| 문법상 허용＋스타일 조언 | `acceptable` | 원문 | `check:style_advisory`와 검수 의견 |
| 문법상 허용＋표기 후보 | `acceptable` | 원문 | `check:orthography_candidate`와 검수 의견 |
| 누락·잡음 | `insufficient_evidence` | 원문 유지 | 대화 복구 예시는 정답과 분리 |
| 타 언어 | `insufficient_evidence` | 원문 유지 | 번역 예시는 정답과 분리 |
| 문법상 허용＋동문서답 | `acceptable` | 원문 | `check:context_mismatch` |
| 문법 오류＋동문서답 | `needs_correction` | 문법만 최소 교정 | `check:context_mismatch` 유지 |

향후 제품 계약을 확장한다면 다음과 같은 분리 필드를 검토할 수 있다. 아직 현재 코드나 v0.1 평가셋 필드로 추가하지 않는다.

```text
style_advisory
orthography_advisory
pronunciation_review
context_mismatch
conversation_recovery
translation_example
```

## 11. 문항별 신뢰도 기록 기준

신뢰도는 모델 확률이 아니라 검수 근거의 충분성을 나타낸다.

| 등급 | 기준 | 예시 |
| --- | --- | --- |
| 높음 | 명백한 활용·조사·종결 오류 또는 완전하고 자연스러운 문장 | `洗うます → 洗います` |
| 중간 | 문체, 상황, 평가 모드에 따라 결론이 달라짐 | JG-065, JG-067, JG-068 |
| 낮음 | 누락, 잡음, 침묵, 원음 부재로 의도를 추정해야 함 | JG-049–JG-060 |

낮은 신뢰도의 문항을 억지로 `acceptable` 또는 `needs_correction`으로 확정하지 않는다. 판단 근거가 부족하면 `insufficient_evidence`를 우선한다.

## 12. 적용한 2차 검수 순서

1. JG-061, 063, 064, 065, 067, 068의 여섯 충돌 레코드를 검수했다.
2. JG-049–060의 누락·잡음·타 언어 처리를 확인했다.
3. JG-033, 043, 064, 065, 067, 068, 072의 교정 피드백 범위를 확인했다.
4. JG-004, 012, 014, 016, 017, 019, 022, 070, 071의 설명을 확인했다.
5. 나머지 명확한 교정 문항과 허용 문항을 검수했다.
6. 합의 결과를 평가셋 원본과 Excel에 익명 `user_reviewed`로 반영했다.
7. 구현 후 데이터 검사, 전체 테스트, RAG 중복 검사를 실행한다.

## 13. 검수 결과 기록 형식

검수표에는 최소한 다음 내용을 남긴다.

| 필드 | 내용 |
| --- | --- |
| 평가셋 ID | `JG-001` 형식의 고유 ID |
| 최종 문법 판단 | `acceptable / needs_correction / insufficient_evidence` |
| 최종 교정문 | 필요할 때만 최소 교정문 입력 |
| 부가 판단 | 문체·표기·발음·문맥·복구·번역 구분 |
| 신뢰도 | 높음·중간·낮음 |
| 검수 의견 | 승인, 수정 근거, 보류 이유 또는 제외 이유 |
| 검수일 | 익명 사용자 검수 이력; 개인 식별자는 저장하지 않음 |

예시:

```text
JG-061 승인 — acceptable, 필러 유지, 신뢰도 높음
JG-065 승인 — acceptable, style_advisory, 신뢰도 중간
JG-067 승인 — acceptable, 표기 후보·원인 미확인, 신뢰도 중간
JG-052 승인 — insufficient_evidence, 누락 내용 추측 금지, 신뢰도 낮음
```

실제 일본어 전문가가 확인하지 않은 문항을 `expert_reviewed`로 표시하지 않는다. 자동 테스트나 모델 간 합의를 사람 검수로 대체하지 않는다.

## 14. 최종 완료 조건

- 72개 문항 모두 승인·수정·보류·제외 중 하나로 처리됐다.
- 모든 판단은 ID, 원문, 문맥을 함께 보고 기록됐다.
- 문법 상태와 문체·표기·발음·문맥 문제가 분리됐다.
- 미완성 문장의 누락 내용을 임의로 생성하지 않았다.
- 교정문은 최소 수정이며 원문의 의미와 말투를 보존한다.
- 문체 대안, 대화 복구 문장, 번역 예시가 골드 교정문과 분리됐다.
- 수정 문항은 재검수를 마쳤다.
- 보류·전문가 검토 대상이 명시됐다.
- 개인 검수자 식별자 없이 검수일이 기록됐다.
- 데이터 구조와 edit 위치 검사를 통과했다.
- 전체 회귀 테스트를 통과했다.
- 평가셋과 학습·few-shot·RAG 자료의 직접 중복 검사를 통과했다.
- 데이터 버전과 SHA-256을 기록했다.

## 15. 최종 원칙 요약

> 문법 판단은 문법만 판단한다.
>
> 문체·표기·발음·문맥은 별도 축으로 기록한다.
>
> 누락된 발화는 추측하지 않는다.
>
> 더 자연스러운 표현을 유일한 정답으로 강제하지 않는다.
>
> 동일 문장도 ID와 문맥이 다르면 별도로 검수한다.
> 사람 검수 전의 일치율은 정확도가 아니다.
