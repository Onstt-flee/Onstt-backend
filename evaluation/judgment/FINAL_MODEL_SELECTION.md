## 1. 최종 결론

현재 테스트한 기준선 중 **학습 없이 운영 API에 바로 투입할 수 있다고 판정한 모델은 없다.** 모든 모델이 사전에 정한 운영 후보 목표를 하나 이상 통과하지 못했다.

후속 Qwen3-4B LoRA 실험에서는 v0.2-D가 봉인된 `holdout_v0.3`의 안전 기준을 통과했다. 기능 플래그 API와 실제 STT 50건 shadow에서는 출력 계약 49/50(98%)이었으나, 원문 보존 위반에만 1회 재시도하는 정책을 추가한 뒤 기존 표본과 비중복인 실제 STT 100건에서 최종 계약 99/100과 성공 99건 p95 1108.711ms로 제한적 staging/shadow 기준을 통과했다. 재시도 1건은 회복되지 않았고 503으로 차단됐다. 원문 보존 프롬프트 v0.2.1, 실제 운영 원문을 쓰지 않은 합성 보강 G, 같은 데이터의 노출 빈도만 고정한 H도 개발셋에서 D의 안전성을 넘지 못해 미채택했다. 따라서 베이스 모델 비교 결론은 유지한다. 이후 봉인된 `holdout_v0.4`에서 D/F 단독을 각각 한 번 비교했으나 허용 교정문이 D 32/50, F 36/50으로 사전 40/50 기준을 모두 실패했다. **최종 운영 승격 후보는 없으며 D는 기본 비활성 연구·staging 기준선으로만 유지한다.** v0.4는 소비 완료됐고 모델 선택용으로 재실행하지 않는다. 마지막 v0.2-J는 소비된 v0.4를 학습 전용으로 편입해 45-step 학습한 뒤, 새 v0.5에서 정확히 한 번 평가했다. J는 구조 120/120·재현율 92%·복합 오류 6/10을 기록했지만 과교정 3/50·정밀도 92%·허용 교정문 36/50으로 사전 기준을 실패했다. J도 미채택했고 v0.5를 소비 완료로 잠갔으며 이번 LoRA 반복을 종료했다. 실제 STT 독립 품질 확인을 위해 기존 shadow 150건을 제외한 30건을 예측 비노출 상태로 봉인했으며 현재 익명 텍스트 라벨을 기다린다. 결정론적 경계 게이트 v0.1은 D 개발 replay에서 판단 70/72·보류 12/12를 기록했다. 실제 저장 STT 340건 dry-run에서는 bypass와 advisory가 모두 0건이어서 아직 운영 API에 연결하지 않았다. 상세는 [holdout v0.3 결과](../../training/judgment/V0.2_DF_HOLDOUT_V0.3_RESULT.md), [기존 50건 shadow 결과](../../training/judgment/JUDGMENT_D_SHADOW_V0.1_RESULT.md), [비중복 100건 shadow 결과](../../training/judgment/JUDGMENT_D_SHADOW_V0.2_RESULT.md), [v0.2-G 결과](../../training/judgment/V0.2_G_TRAIN_AND_DEV72_RESULT.md), [v0.2-H 결과](../../training/judgment/V0.2_H_TRAIN_AND_DEV72_RESULT.md), [경계 게이트 결과](../../training/judgment/DETERMINISTIC_BOUNDARY_GATE_V0.1_RESULT.md), [v0.2-J 최종 결과](../../training/judgment/V0.2_J_HOLDOUT_V0.5_RESULT.md)를 따른다.

다만 다음 판단 전용 LoRA 개발에 사용할 수 있는 모델은 아래 두 개로 좁힌다.

1. **주 후보: `Qwen/Qwen3-4B-Instruct-2507`**
   - 첫 판단 전용 LoRA의 학습 베이스로 사용한다.
   - 8B와 원시 판단·교정 내용 성능이 거의 같으면서 가중치와 지연시간 부담이 작다.
   - 목표인 “가능한 작은 모델에서 정확한 성능”에 가장 잘 맞는다.
2. **보조 후보: `Qwen/Qwen3-8B`**
   - 동일 데이터로 학습했을 때 4B의 한계를 넘는지 확인하는 상한 기준선과 품질 비교군으로 사용한다.
   - 현재 엄격 점수는 가장 높지만 4B 대비 내용상 개선이 매우 작고 실행 비용이 크므로 첫 학습 대상은 아니다.

여기서 **사용 가능**은 “고정 평가셋과 별도의 학습 데이터로 LoRA를 만들고 재평가할 가치가 있음”을 뜻한다. 현재 두 베이스 모델 모두 계약 실패와 교정 누락이 많으므로 **현 상태로 학습자에게 자동 교정을 확정 제공하는 운영 모델은 아니다.**

`Qwen/Qwen3-14B`는 학습 후보가 아니라 **고용량 정확도 상한 비교 기준선**으로 유지한다. 원시 내용 품질은 가장 높았지만 계약 성공률은 4B와 같고 과교정·지연시간·메모리 비용이 늘어, 현재 목적에선 4B·8B보다 우선할 근거가 부족하다.

- 테스트한 11개 안에서 Qwen3 4B·8B를 학습 후보로 남기는 판단: **높음**. 14B를 포함해도 비용 대비 결과 순위가 뒤집히지 않았다.
- 4B를 8B보다 먼저 학습하는 판단: **중간~높음**. 현재 72문항에서 내용 성능이 거의 같고 효율 차이가 명확하다.
- 실제 운영 품질에 대한 신뢰도: **중간 이하**. 독립 미사용 합성 시험은 통과했지만 복합 오류 성능이 낮고, 실제 STT shadow도 98% 구조 성공률로 승격 기준을 실패했다. 일본어 전문가 검수와 라벨 있는 실제 표본 품질 검증도 남아 있다.

## 4. 평가셋 구성과 판단 범위

평가셋은 익명 사용자 검수가 기록된 합성 문항 72개다. 일본어 전문가 인증 데이터는 아니다.

| 정답 판단 | N5 설정 | N4 설정 | 합계 |
| --- | ---: | ---: | ---: |
| `acceptable` | 24 | 9 | 33 |
| `needs_correction` | 24 | 3 | 27 |
| `insufficient_evidence` | 10 | 2 | 12 |
| 합계 | 58 | 14 | 72 |

추가 구성은 다음과 같다.

- 복합 오류 문항: 4개
- 필러·문체·표기·STT·문맥을 분리하는 경계 문항: 12개
- 교정 오류 유형: 조사, 동사 활용, 형용사 활용, 서술어 활용, 명사 수식 연결, 시제 불일치
- 보류 유형: 빈 입력, 잡음, 머뭇거림만 있는 입력, 명시적 누락, 일본어가 아닌 입력
- 정상 반례: 이동 수단의 `で`, 이동 경로의 `を`, 구어체 생략·축약, 짧은 문맥 응답, 필러 보존 등

`learner_level`은 모델에 제공하는 학습자 설정일 뿐 공인 JLPT 분류가 아니다. 문법 판단은 문체 취향, 더 자연스러운 대안, 표기 조언, 발음 추정, 질문 관련성 평가와 분리한다.

## 5. 모델 입력과 출력 계약

### 5.1 모델에 제공하는 입력

모델에는 아래 세 값만 전달한다.

- `text`: 판단할 일본어 또는 STT 전사 텍스트
- `context`: 질문·상황 문맥, 없으면 `null`
- `learner_level`: `N5` 또는 `N4`

문항 ID, 정답 판단, 기준 교정문, 허용 교정 후보, 오류 태그, 검수 정보는 전달하지 않는다. 평가 정답 노출을 방지하기 위해 실행기와 채점기를 분리한다.

### 5.2 요구 출력

모델은 설명문이나 Markdown 없이 정확히 하나의 JSON 객체를 출력해야 한다.

```json
{
  "decision": "acceptable | needs_correction | insufficient_evidence",
  "corrected_text": "원문 또는 최소 교정문",
  "edits": [
    {
      "start": 0,
      "end": 1,
      "source": "원문 구간",
      "replacement": "대체 문자열",
      "error_type": "허용 오류 유형"
    }
  ],
  "reason_ko": "짧은 한국어 판단 근거"
}
```

엄격 계약은 다음을 모두 검사한다.

1. 표준 JSON 객체 하나이며 중복 키, 비표준 상수, 코드 펜스, 바깥 설명이 없어야 한다.
2. 최상위 필드는 `decision`, `corrected_text`, `edits`, `reason_ko` 네 개만 있어야 한다.
3. `decision`은 세 허용 값 중 하나여야 한다.
4. `acceptable`과 `insufficient_evidence`는 원문을 보존하고 `edits`가 비어 있어야 한다.
5. `needs_correction`은 의미를 보존한 최소 교정과 실제 변경 edit가 있어야 한다.
6. edit 위치는 원문의 Unicode 코드 포인트 기준 0부터 시작하는 `[start, end)`다.
7. `source`는 지정한 원문 구간과 정확히 일치해야 한다.
8. edit는 정렬되고 겹치지 않으며, 모두 적용한 결과가 `corrected_text`와 정확히 같아야 한다.
9. `error_type`은 정해진 여섯 유형 중 하나여야 한다.

계약 검사는 출력 구조와 문자열 복원을 보장할 뿐, 교정의 언어학적 타당성이나 한국어 근거의 정확성을 증명하지 않는다.

## 6. 평가 지표와 계산 기준

엄격 지표에서는 계약을 통과한 출력만 모델 판단으로 인정한다. 전송 실패나 계약 실패는 `system_failure`이며, 보류 정답으로 대신 계산하지 않는다.

### 6.1 시스템·계약 지표

- **전송 성공률** = HTTP 응답을 정상 수신한 문항 수 / 72
- **JSON/계약 성공률** = 엄격 계약을 전부 통과한 문항 수 / 72
- **시스템 실패 수** = 전송 또는 계약 실패 문항 수
- **3분류 판단 정확도** = 계약 유효하고 정답 판단과 일치한 문항 수 / 72

계약 실패가 많은 모델의 과교정률 0%는 안전성을 의미하지 않는다. 판단 자체가 유효하지 않아 과교정으로 집계될 기회가 없었을 수 있기 때문이다.

### 6.2 문법 판단 지표

- **과교정률** = 정답이 `acceptable`인데 유효 출력이 `needs_correction`인 수 / 33
- **교정 탐지 정밀도** = 실제 교정 문항을 맞힌 유효 `needs_correction` 수 / 유효 `needs_correction` 예측 수
- **교정 탐지 재현율** = 실제 교정 문항을 맞힌 유효 `needs_correction` 수 / 27
- **올바른 보류율** = 보류 정답에서 유효하게 `insufficient_evidence`를 반환한 수 / 12
- **명확 문항 처리율** = 보류가 정답이 아닌 60문항에서 유효하게 보류 이외의 판단을 반환한 수 / 60

명확 문항 처리율은 정확도와 다르다. 모델이 문항을 처리했는지를 보며, 그 판단이 맞았는지는 3분류 정확도와 함께 확인한다.

### 6.3 교정문·edit 지표

- **정규 교정문 완전 일치율** = 유효한 교정 판단 중 `corrected_text`가 대표 교정문과 같은 수 / 27
- **허용 교정문 일치율** = 유효한 교정 판단 중 `corrected_text`가 대표·허용 후보 중 하나인 수 / 27
- **탐지 성공 후 허용 교정률** = 허용 교정문 수 / 실제 오류를 탐지한 유효 교정 판단 수
- **정규 edit 완전 일치율** = 모델의 edit 배열이 기준 edit 배열과 같은 문항 수 / 27
- **edit micro 정밀도·재현율** = 모든 문항의 `(ID, 위치, 원문, 대체문, 오류 유형)` edit를 합쳐 계산
- **복합 오류 완전 처리율** = 복합 오류 4문항에서 필요한 모든 기준 edit를 포함한 문항 비율

`accepted_corrections`는 가능한 일본어 표현을 전부 열거하지 않는다. 목록 밖이지만 자연스러운 교정은 자동으로 확정 오답 처리하지 않고 사람 검토 대상으로 남긴다.

### 6.4 세부 분석과 성능 지표

- 오류 유형별 정밀도·재현율
- N5/N4 설정별 계약 성공·판단 정확도
- 경계 태그별 결과: 필러 보존, 문체 조언, 표기 후보, 문맥 일치·불일치, 발음/STT 귀속 불명 등
- 평균·p50·p95 지연시간
- 프롬프트·완료 토큰 수와 요청 지연시간 기준 처리량
- 모든 비율의 분자·분모와 Wilson 95% 신뢰구간

`reason_ko`의 언어학적 정확성, 의미 보존, 최소 교정의 적절성, 학습자 친화성은 현재 자동 채점 대상이 아니며 별도 사람 검수가 필요하다.

## 7. 현재 잠정 통과 기준

코드에 고정된 초기 후보 통과 기준은 다음과 같다.

| 지표 | 통과 기준 | 목적 |
| --- | ---: | --- |
| JSON/계약 성공률 | 99% 이상 | 운영 파서 안정성 |
| 과교정률 | 2% 이하 | 맞는 문장을 망가뜨리는 위험 억제 |
| 교정 탐지 정밀도 | 95% 이상 | 불필요한 교정 최소화 |
| 교정 탐지 재현율 | 80% 이상 | 실제 오류 누락 억제 |
| 명확 문항 처리율 | 85% 이상 | 과도한 보류와 시스템 실패 방지 |

다섯 조건을 모두 통과해야 `meets_all_targets`가 참이 된다. 현재 11개 모델은 모두 거짓이다.

허용 교정문 일치, 올바른 보류, 복합 오류, 의미 보존, 지연시간에는 아직 코드로 고정된 운영 임계값이 없다. 이 항목은 LoRA 학습 전에 운영 요구사항과 함께 별도로 확정해야 하며, 현재 점수만 보고 생략해서는 안 된다.

## 8. 실제 평가 절차

1. **데이터 고정**: 72개 ID, 검수 상태, 데이터 SHA-256과 RAG 직접 중복을 확인한다.
2. **실행 환경 기록**: 모델 artifact·revision·가중치 해시, 런타임, dtype, context, seed와 채팅 템플릿을 manifest에 남긴다.
3. **프롬프트 고정**: 정답을 제외한 세 입력 필드만 같은 `judgment-v0.1` 프롬프트로 보낸다.
4. **생성 조건 고정**: `temperature=0`, `top_p=1`, `max_tokens=512`로 실행한다.
5. **스모크 테스트**: `JG-001` 한 문항으로 서버 연결과 모델명을 확인한다.
6. **전체 실행**: 72개를 한 번씩 호출하고 요청, 원시 응답, 지연시간, 계약 검사 결과를 JSONL에 보존한다.
7. **산출물 검증**: 데이터·프롬프트·입력 순서·결과 파일 SHA-256과 manifest를 대조한다.
8. **엄격 오프라인 채점**: 계약 실패를 복구하거나 필드를 보충하지 않고 시스템 실패로 포함해 공식 지표를 계산한다.
9. **원시 출력 진단**: 계약 실패 원인이 문법 판단인지 Unicode edit 위치인지 구분하기 위해 별도 진단한다. 이 값은 공식 점수로 승격하지 않는다.
10. **비교와 선정**: 품질 지표를 먼저 비교한 뒤 모델 크기, 메모리, 지연시간을 고려해 가장 작은 충분한 후보를 선택한다.

재현 명령 예시는 다음과 같다.

```bash
# 데이터·검수·RAG 직접 중복 검사
venv/bin/python -B -m evaluation.judgment.dataset \
  --require-reviewed --rag-dir rag_data

# 실행 중인 OpenAI 호환 서버에 대해 1문항 확인
venv/bin/python -B -m evaluation.judgment.runner \
  --endpoint http://127.0.0.1:1234/v1/chat/completions \
  --model MODEL_ID \
  --output evaluation/judgment/runs/MODEL-smoke.jsonl \
  --id JG-001

# 전체 실행: --id를 제거하고 새 출력 파일 사용
venv/bin/python -B -m evaluation.judgment.runner \
  --endpoint http://127.0.0.1:1234/v1/chat/completions \
  --model MODEL_ID \
  --output evaluation/judgment/runs/MODEL-full.jsonl

# 하나 이상의 전체 실행 검증·채점·비교
venv/bin/python -B -m evaluation.judgment.scorer \
  --run evaluation/judgment/runs/MODEL-full.jsonl \
  --output-prefix evaluation/judgment/runs/MODEL-report
```

서로 다른 데이터, 문항 순서, 프롬프트 또는 생성 조건의 결과는 기본 비교가 거부된다. 의도적인 설정 실험일 때만 `--allow-mixed-config`를 사용하고 차이를 문서화한다.

## 9. 후보별 핵심 탈락 사유

- **Qwen3.5 0.8B·2B**: 계약 준수와 과교정 제어가 부족하고 유효 교정 판단이 없다.
- **Qwen3.5 4B**: 작은 모델 중 개선은 있었지만 계약 19/72, 교정 재현 1/27로 부족하다.
- **Phi-4 mini**: 원시 출력에서 오류를 일부 찾았으나 정상 33개 중 14개를 교정 대상으로 보는 과교정이 컸다. 엄격 과교정 0은 계약 실패 때문에 생긴 착시다.
- **Qwen3-14B**: 원시 판단 60/72, 허용 교정문 19/27로 내용 품질은 최고였지만 엄격 계약 45/72, 원시 과교정 5/33, 평균 지연시간 3,561ms였다. 고용량 상한 비교군으로 유지하고 첫 LoRA 대상에서는 제외한다.
- **RakutenAI 1.5B**: 대부분 한국어 시스템 프롬프트나 입력을 반복했고 올바른 계약 JSON을 만들지 못했다.
- **llm-jp 1.8B·3.7B**: 호환 채팅 템플릿으로 system 지시를 보존해도 `needs_correction`을 한 번도 선택하지 않았다.
- **기존 일반 튜터 LoRA**: 같은 Qwen3-4B 베이스보다 크게 악화해 JSON 대신 한국어 튜터 문장을 출력했다. 판단모델에 병합하거나 재사용하지 않는다.

## 10. 한계와 다음 판정 단계

현재 결과는 **초기 모델 선택용 진단**이지 운영 품질 인증이 아니다.

- 72문항은 작은 합성 평가셋이며 일본어 전문가 검수가 아니다.
- N4 교정 문항과 복합 오류 문항이 특히 적어 세부 성능의 신뢰구간이 넓다.
- 기존 결과를 보며 개발하게 되므로 이후 이 평가셋은 개발용 진단셋으로 간주해야 한다.
- RAG 검사는 정규화 문자열의 직접 일치만 찾으며 모델 사전학습 오염이나 의미상 유사 문장을 배제하지 못한다.
- 자동 점수는 자연스러움, 의미 보존, 설명 품질을 완전히 평가하지 못한다.

현재 개발 주기의 최종 판정은 다음과 같다.

1. v0.2-J까지 계획된 Qwen3-4B LoRA 학습을 종료했다.
2. v0.5 단일 실행에서 안전·품질 기준을 모두 충족한 모델이 없으므로 운영 API 기본 판단기로 승격하지 않는다.
3. v0.2-D는 과거 staging/shadow 재현용 기준선, v0.2-J는 최종 연구 결과로만 보존한다. 둘 다 학습자 노출 기본값은 비활성이다.
4. 사람 상세 검수와 음성·발음 평가는 사용자 결정에 따라 후순위로 유지한다.
5. 향후 재개 시에는 v0.5를 재사용하지 않고, 새 데이터 계보와 새 미사용 시험지를 먼저 고정한 별도 개발 주기로 시작한다.

최종 11개 베이스 비교 원본은 Git 제외 경로 `evaluation/judgment/runs/all-baselines-comparison-v02.json`과 `.md`에 보존하며, Git에는 모델별 재현 요약과 v0.2-J 최종 결과를 `evaluation/judgment/results/`에 유지한다.
