# feedback-v0.8 실제 저장 STT 200건 비노출 shadow 결과

기준일: 2026-10-20

## 결론

GPU `judgment-v0.2-D`와 `feedback-verifier-v0.8-stage2-recovery-style`의 2단계
피드백 경로를 기존 비공개 저장 STT snapshot 200건에서 실행했다. 판단 계약과 무결성은
통과했지만 피드백 audit coverage가 `195/198`(98.48%)로 사전 99% 기준에 미달했다.
따라서 v0.8은 내부 holdout 통과 상태는 유지하되 실제 shadow 운영 게이트는 실패로 기록한다.
기능 플래그, 관리자 경고, 학습자 노출과 자동 재학습은 활성화하지 않는다.

이 실행은 정답 라벨과 음성 근거가 없는 운영 계약 검증이다. 일본어 문법 정확도,
과교정률, 발음 성능 또는 전문가 인증 근거로 사용할 수 없다.

세 실패 작업은 `1분 → 5분` 백오프와 최대 3회 정책을 실제로 거친 뒤 모두
`failed/contract`로 격리됐다. HTTP 전송은 성공했지만 계약 파싱을 통과하지 못했으며,
부분 audit이나 임의 보정 결과는 저장하지 않았다.

후속 읽기 전용 진단에서 세 작업을 각각 한 번만 재호출해 단계별 오류를 분리했다.
세 건 모두 Stage 1 판정 계약은 통과했고 `disagree` 뒤의 Stage 2 권장 판단·교정안
계약에서 실패했다(`contract_stage2=3`). 진단 전후 격리 DB SHA-256은 동일하며,
원문·원시 출력·판단 ID는 추적 결과에 기록하지 않았다. 이는 실패 위치 확인일 뿐
재평가·품질 최적화·모델 선택 근거가 아니다.

## 판정

통과한 기준:

- 판단 계약 성공률 99% 이상
- 판단 재시도율 5% 이하
- 판단 p95 2.5초 이하
- 실패 작업 3회 후 안전 격리
- 판단 불변성
- job·audit 중복 0건

실패한 기준:

- 피드백 audit coverage 99% 이상: 실제 98.48%

따라서 v0.8을 운영 또는 학습자 노출 대상으로 승격하지 않는다. 실패 위치는 Stage 2로
확정됐으므로, 다음 후보는 Stage 1을 변경하지 않고 Stage 2 출력 계약 안정성만 보강해야
한다. 새 후보가 생기기 전에는 이 라벨 없는 snapshot을 품질 최적화나 모델 선택에
사용하지 않는다.
