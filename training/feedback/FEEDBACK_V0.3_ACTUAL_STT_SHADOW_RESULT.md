# feedback-v0.3 실제 저장 STT 200건 비노출 shadow 결과

기준일: 2026-10-16

## 결론

GPU `judgment-v0.2-D`와 `feedback-verifier-v0.3`의 실제 저장 STT 200건 비노출
운영 shadow가 계약·재시도·불변성 기준을 통과했다. 기능 플래그 기본 비활성,
학습자 비노출, 기존 판단 불변 원칙은 유지한다.

이 결과는 정답 라벨과 음성 근거가 없는 운영 안정성 검증이며 일본어 문법 정확도,
과교정률, 발음 평가 또는 일본어 전문가 인증 근거가 아니다.

## 입력과 실행 범위

- 실제 저장 일본어 STT 중 비중복 200건
- 정확한 대화 문맥을 복원할 수 없어 `context=null`
- 원문과 원시 모델 출력은 Git 제외 경로에만 저장
- 추적 파일에는 집계와 SHA-256만 기록
- GPU BF16 판단모델과 GPU BF16 피드백모델 사용
- Raspberry Pi 결과는 포함하지 않음

## 판단모델 결과

| 항목 | 결과 |
| --- | ---: |
| 입력 | 200 |
| 전송 성공 | 200 |
| 최초 호출 계약 성공 | 195 |
| 재시도 | 5 |
| 재시도 복구 | 3 |
| 재시도 후 최종 실패 | 2 |
| 최종 계약 성공 | 198/200 (99.0%) |
| 재시도율 | 2.5% |
| p50 | 858.611ms |
| p95 | 1230.975ms |
| 모델 호출 | 205 |

재시도는 `acceptable` 또는 `insufficient_evidence`가 원문을 보존하지 않은 경우에만
정확히 한 번 수행했다. 최종 실패 2건은 잘못된 판단으로 저장하지 않고 차단했다.

최초 실행기는 이 운영 재시도를 사용하지 않아 196/200만 기록했다. 해당 실행은 최종
운영 근거에서 제외하고, 운영과 동일한 재시도 정책을 연결한 뒤 같은 고정 입력으로
복구 검증을 다시 수행했다.

## 피드백모델 결과

| 항목 | 결과 |
| --- | ---: |
| 생성된 audit job | 198 |
| 성공 audit | 197 |
| 3회 계약 실패 후 격리 | 1 |
| audit coverage | 197/198 (99.49%) |
| verdict | agree 188 / disagree 9 |
| p50 | 1192.721ms |
| p95 | 1269.438ms |
| 중복 job / audit | 0 / 0 |

실패 1건은 `1분 → 5분` 백오프를 거쳐 총 3회 시도한 뒤 `failed/contract`로
격리됐다. 작업이 유실된 것이 아니며 관리자 조사 대상으로 남았다. 기존 판단 응답과
판단 레코드에는 영향을 주지 않았다.

`agree/disagree` 비율은 두 모델의 일치 집계일 뿐 정확도나 검수 성능으로 해석하지 않는다.

## 무결성과 안전 경계

- 원본 `stt_data.db` SHA-256은 실행 전후 동일
- 격리 DB의 판단 snapshot은 피드백 실행 전후 동일
- 중복 job과 audit 0건
- 모델·runtime 정보는 피드백모델 입력에서 제외
- 원문, 교정문, 사용자 ID는 추적 집계에 포함하지 않음
- 기능 플래그 기본값 OFF 유지
- 학습자 경고와 운영 기본 활성은 승인하지 않음
- 사람 독립 품질 검수 전 자동 학습 데이터 편입 금지

## 검증

- 전체 회귀 테스트: 360/360
- 프로젝트 가상환경 `pip check`: 통과
- Qwen3 PEFT 가상환경 `pip check`: 통과
- 체크포인트 감사: 미분류·금지 파일·비밀 패턴·스테이징 0건
- 검증 시점의 커밋·푸시: 수행하지 않음

## 관리자 반복 이슈 집계

최종 격리 SQLite를 read-only로 열어 관리자 투영을 검증했다. 목록 197건과 상세
197건은 정상 조회됐고, 완료 작업 재시도 가능 건수는 0건이었다. DB SHA-256은
검사 전후 `988f21db...29db`로 동일했다.

- 이슈 그룹: 8개
- 상태: `emerging` 6개, `recurrent` 2개
- 모델 불일치 멤버십: 14건
- 최종 계약 실패 경고: 1건
- `unreviewable`: 0건

반복 상태는 audit 행 수가 아니라 고유 `judgment_id` 수로 계산한다. 여러 피드백모델
버전이 같은 판단을 다시 검수해도 반복 횟수를 부풀리지 않는다. 원문·교정문·사용자 ID는
집계 결과에 포함하지 않으며, 정답 라벨이 없으므로 반복 그룹을 실제 오류로 확정하지 않는다.

## 관리자 HTTP·Swagger 스모크

실제 격리 SQLite의 임시 복사본으로 loopback API를 실행했다. `/docs`와
`/openapi.json`은 200이었고 관리자 경로 6개가 OpenAPI에 포함됐다.

- 무인증 audit 목록: 401
- 인증된 health/list/issues/detail: 200
- 성공 작업 retry: 409
- 피드백 모델 중단 readiness: 503 `model_unavailable`
- 기능 플래그 비활성 health: 503
- 목록·health·상세 원문 노출: 없음
- 원본 DB와 임시 복사본: 실행 전후 SHA-256 동일

임시 관리자 토큰은 결과에 저장하지 않았고 테스트 API 프로세스는 모두 종료했다.
이 검증도 접근 제어·운영 배선 근거일 뿐 언어 품질이나 운영 기본 활성 근거가 아니다.
