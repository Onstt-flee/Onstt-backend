# feedback-v0.3 조사 경계 진단 결과

기준일: 2026-10-17

## 결론

`feedback-verifier-v0.3`는 새 자동 생성 조사 경계 진단 40건에서 오류 문장 20건은 모두
찾았지만, 올바른 판단 20건도 모두 `disagree`로 처리했다. 특히 권장 판단은 원래와 같은
`acceptable`이면서 issue code는 `false_negative`인 내부 모순을 생성했다.

기존 파서는 JSON 구조가 맞다는 이유로 이를 허용했으나, 이제 문제 유형과 권장 decision의
의미 조합도 검증해 20건을 모두 계약 위반으로 차단한다. 잘못된 audit 저장은 막지만 강화 후
계약 성공은 `20/40`이므로 현재 모델의 운영 활성은 계속 금지한다.

## 진단 구성

| 유형 | 건수 | 목적 |
| --- | ---: | --- |
| 존재 장소 `で` 오류 | 10 | false negative 탐지 |
| 올바른 존재 장소 `に` | 10 | 정상 판단 보호 |
| 올바른 동작 장소 `で` | 10 | 조사 기능 구별 |
| 목적지 `を` 오류 | 10 | false negative 탐지 |

기존 피드백 학습 데이터와 holdout v0.1~v0.4의 원문 및 완전 입력 중복은 0건이다.
모든 문항은 `generated_validated`이며 사람·전문가 검수 자료가 아니다.

## 결과

| 지표 | 기존 구조 파서 | 의미 계약 강화 후 |
| --- | ---: | ---: |
| 계약 성공 | 40/40 | 20/40 |
| 허위 불일치율 | 100% | 0% (모순 출력 차단) |
| 불일치 정밀도 | 50% | 100% |
| 불일치 재현율 | 100% | 100% |
| 권장 decision 정확도 | 100% | 100% |
| canonical 교정문 일치 | 18/20 | 18/20 |
| p95 | 2.565초 | 2.565초 |

목적지 오류 1건은 canonical `に` 대신 허용 가능한 `へ`를 사용했으므로 언어적으로 허용되는
교정은 19/20이다. `FVD-EP-01-010`은 `窓際で植木鉢があります`를
`窓際の植木鉢があります`로 바꿔 최소 존재 장소 교정에 실패했다.

## 계약 강화

- `false_negative` → 권장 `needs_correction`
- `false_positive` → 권장 `acceptable`
- `should_abstain` → 권장 `insufficient_evidence`
- `unnecessary_abstention` → 권장 값은 `insufficient_evidence`가 아님

모델 프롬프트와 백엔드 파서에 같은 규칙을 적용했다. 기존 원시 결과는 수정하지 않고 별도
재파싱 산출물로 영향만 계산했다.

## 다음 결정

- 기능 플래그 OFF와 관리자 비노출 기본값 유지
- 현재 진단은 소비 완료로 잠그고 재실행·맞춤 튜닝 금지
- 강화된 프롬프트는 새로운 미사용 진단으로만 평가
- 프롬프트만으로 정상 판단 보호가 회복되지 않으면 v0.4 LoRA 학습 데이터에 다양한 정상
  근거 표현과 issue/decision 일관성 반례를 추가

## 강화 프롬프트 신규 진단 v0.2

v0.1과 학습·holdout 전체에 원문 및 완전 입력 중복이 없는 새 40건을 만들고, 강화된 프롬프트로 정확히 한 번 실행했다.
데이터는 존재 장소 오류 10건, 올바른 존재 장소 10건, 올바른 동작 장소 10건, 목적지 오류 10건으로 균형을 맞췄다.

| 지표 | v0.2 결과 |
| --- | ---: |
| 계약 성공 | 33/40 (82.5%) |
| 의미 계약 차단 | 7/40 |
| 허위 불일치율 | 0% |
| 불일치 정밀도 | 100% |
| 불일치 재현율 | 75% |
| 권장 decision 정확도 | 70% |
| 허용 교정문 일치율 | 70% |
| p95 | 2.618초 |

실패 13건은 다음 세 유형으로 분리됐다.

- 존재 장소 `で→に` 오류 누락 5건
- 정상 존재·동작 장소에 `false_negative + acceptable`을 함께 낸 의미 모순 7건(파서가 저장 전 차단)
- 목적지 `を` 오류를 타 언어로 오인해 보류한 1건

강화 규칙은 v0.1의 정상 문장 허위 불일치 20/20을 v0.2의 저장 가능한 허위 불일치 0건으로 줄였다.
그러나 계약 82.5%, 재현율 75%, 교정문 70%이므로 프롬프트만으로는 품질을 회복하지 못했다.

따라서 현재 v0.3은 기능 플래그 OFF를 유지하고, 다음 단계는 다양한 정상 근거 표현과 issue/decision 일관성 반례를 포함한 feedback-v0.4 LoRA 학습이다.
v0.2 진단은 소비 완료이며 v0.4 학습이나 모델 선택에 재사용하지 않는다.
