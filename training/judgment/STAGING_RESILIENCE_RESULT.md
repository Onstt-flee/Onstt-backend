# 판단모델 staging 동시성·장애 주입 결과

기준일: 2026-10-06

## 결론

프로세스 로컬 상태 집계에 합성 이벤트 1,000개를 16개 worker로 동시에 기록했을 때 모든 카운터가 기대값과 정확히 일치했다. 판단 API 경계에 timeout, 원문 보존 재시도 재실패, DB 저장 실패를 주입했을 때 실패는 정상 판단으로 저장되지 않았고 익명 실패 범주와 `degraded` 상태로 집계됐다.

이 결과는 **집계 코드의 thread safety와 장애 처리 경계 검증**이다. 실제 vLLM 추론 처리량, FastAPI HTTP 동시 처리량, GPU 메모리 상한이나 문법 정확도 측정이 아니다.

## 합성 동시성 probe

실행 명령:

```bash
venv/bin/python -B -m scripts.run_judgment_resilience_probe
```

조건:

- worker: 16
- 동시 제출 이벤트: 999
- 마지막 상태를 결정론적으로 고정하는 성공 이벤트: 1
- 전체 요청: 1,000
- 원문·발화 ID·문맥·교정문·모델 응답: 사용하지 않음
- DB·네트워크·모델 호출: 없음

검증 결과:

| 항목 | 기대 | 실제 |
| --- | ---: | ---: |
| 전체 요청 | 1,000 | 1,000 |
| 모델 호출 집계 | 900 | 900 |
| 성공 | 700 | 700 |
| 실패 | 200 | 200 |
| 기능 비활성 사전 거부 | 100 | 100 |
| 재시도 사용 | 200 | 200 |
| 재시도 회복 | 100 | 100 |
| 유효 지연시간 표본 | 700 | 700 |
| 카운터 불일치 | 0 | 0 |

성공 결정 분포는 `acceptable=600`, `needs_correction=100`이고, 실패 분포는 `timeout=100`, `preservation_retry_failed=100`이다. 수치는 집계 분기 검사용 합성 비율이며 모델 품질 분포가 아니다.

## API 장애 주입

### Timeout

- `JudgmentServiceError`에 timeout을 주입했다.
- API 경계는 HTTP 503으로 닫혔다.
- `judgment_results` 저장은 0건이었다.
- 상태에는 `timeout=1`만 기록되고 원시 endpoint 오류 문자열은 노출되지 않았다.

### 원문 보존 재시도 재실패

- 두 번째 시도까지 실패한 오류 메타데이터를 주입했다.
- API 경계는 HTTP 503으로 닫혔고 DB 저장은 0건이었다.
- 실패 1건, 재시도 1건, 회복 0건, `preservation_retry_failed=1`로 집계됐다.
- 원시 출력과 최초 계약 오류 문자열은 상태 응답에 포함되지 않았다.

### DB 저장 실패

- 유효한 모델 결과 뒤 `create_judgment` 저장 실패를 주입했다.
- 성공 건수는 증가하지 않았고 `persistence_failure=1`, 상태 `degraded`로 기록됐다.
- 잘못된 성공 응답이나 판단 결과 행은 생성되지 않았다.

## 테스트와 경계

- 전용 장애·동시성 테스트 4개가 통과했다.
- 상태 집계는 단일 프로세스 메모리이며 여러 Uvicorn worker 사이에서 합산되지 않는다.
- probe의 실행 시간과 event rate는 Python 집계 코드 내부 수치이므로 API SLA나 모델 처리량으로 사용하지 않는다.
- 실제 HTTP 동시 부하와 vLLM 포화 시험은 운영 기본 활성화 전에 별도 임시 DB·합성 입력 환경에서 수행한다.
- 기능 플래그 기본값은 계속 `JUDGMENT_ENABLED=false`다.
- 사람 검수, 음성 평가, `holdout_v0.4` 실행과 추가 모델 학습은 수행하지 않았다.
