# 판단모델 v0.2-D 보강 설계와 시험지 봉인

상태: **설계·데이터 생성·45-step 학습·72문항 개발셋 비교 완료**. v0.2-C는 기존 holdout의 운영 기준 미달이다. v0.2-D는 개발셋 안전 임계값을 충족했지만 교정문 회귀로 운영 채택을 보류한다. 새 120문항 holdout에는 아직 모델 추론을 실행하지 않았다. 상세는 [C↔D 개발셋 비교](V0.2_D_DEV72_COMPARISON.md)를 따른다.

## 먼저 고정한 미사용 시험지

- 경로: `evaluation/judgment/holdout_v0.2.jsonl`
- SHA-256: `a2ae7f655953f617e2f56219c2065ea5cc68118f95a7492fe048e23669b2736d`
- 120문항: 정상 50, 교정 50(단일 40·복합 10), 판단 불충분 20
- 경로 조사 `を`, 보통체 유지, 존재 장소 `に/で`, い형용사 과거, 필러, STT 표기, 영어·한국어 입력과 누락 구간을 포함한다.
- 정규화 정확 중복 0건: 기존 72문항 개발셋, 공개된 150문항 holdout, v0.2-C 학습 데이터 628문항, RAG JSON 대상
- 기존 세 데이터셋과 문자 3-gram Jaccard ≥0.85 근접 중복 0건; 관측 최대 0.625. 이 검사는 의미상의 중복이나 사전학습 중복까지 배제하지 않는다.
- 상태 `generated_validated`; 사용자·일본어 전문가 검수 또는 언어학적 완전성 인증이 아니다.

해시와 감사 대상 파일별 해시는 `evaluation/judgment/holdout_v0.2.manifest.json`에 있다. 현재 작업트리의 해시 고정 상태이며, Git 체크포인트 커밋은 별도 승인 전까지 하지 않는다. v0.2-D의 데이터·프롬프트·어댑터가 고정되기 전에는 이 시험지에서 어떤 모델의 응답도 실행하거나 열지 않는다.

추가 후보는 정상·오류·보류를 함께 포함하는 **자동 검증 120문항**으로 생성했다. 배분은 정상 60, 교정 40, 보류 20이며 복합 오류 교정은 10개다. 데이터·해시와 검증 결과는 [v0.2-D 데이터 결과](V0.2_D_DATA_RESULT.md)에 기록했다. 원문의 의미·문체·필러는 그대로 두고 문법 오류만 `corrected_text`에 반영한다. 영어·한국어의 일본어 번역은 정답 교정문이 아니다. 데이터 생성기는 `generated_validated`만 부여하고 사용·전문가 검수로 표시하지 않는다.

생성 시에는 개발셋, 기존·신규 holdout, 기존 학습 데이터와 RAG JSON을 대상으로 정규화 정확 중복을 거부하고, 기존 holdout과 새 holdout의 입력·교정문을 학습 예시로 사용하지 않는다. 템플릿만 바꾸는 근접 복제도 문자 3-gram 유사도 감사로 탐지한다. 어휘와 문맥은 holdout에서 역으로 가져오지 않고 별도의 목록에서 만든다.

## 학습·평가 실행 순서

1. 생성 규칙, 레코드 수, 분할과 SHA-256을 고정하고 데이터 유효성·누수 검사를 통과한다.
2. v0.2-C와 같은 Qwen3-4B 기반, seed 42, 45-step, LoRA 하이퍼파라미터, 출력 계약 v0.2를 사용하되 **새 어댑터 경로**에 학습한다. 같은 step에서 데이터 혼합 비율이 달라지는 한계도 기록한다.
3. 개발셋 72문항에서 v0.2-C·동일 계약 v0.2-B 대조군과 실패 유형을 비교한다. 개발셋은 결함 진단용이지 최종 선택 증거가 아니다.
4. 후보 데이터·어댑터·프롬프트·채점 기준을 확정한 뒤 새 `holdout_v0.2`에서 v0.2-C와 v0.2-D를 **동일 설정으로 한 번씩** 실행한다. 결과를 본 뒤 같은 시험지에 맞춰 재학습하거나 기준을 바꾸면 더 이상 blind라고 부르지 않는다.
5. 운영 후보 기준은 JSON/구조 ≥99%, 과교정 ≤2%, 교정 탐지 정밀도 ≥95%, 재현율 ≥80%, 명확 문항 처리 ≥85%다. 최소 교정문 일치·복합 오류 완전 교정·올바른 보류는 v0.2-C와 함께 비교하고 감소 시 원인 검토한다.

현재 미사용 시험지는 120문항으로 작고 자동 생성 정답이다. 기준 통과는 **오프라인 후보 선별**일 뿐, 일본어 전문가 인증이나 실제 STT 현장 성능을 보장하지 않는다. 하나라도 핵심 안전 기준을 실패하면 FastAPI·Swagger 통합을 계속 보류한다.
