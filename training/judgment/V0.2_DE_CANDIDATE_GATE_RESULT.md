# v0.2-D 판단 + v0.2-E 교정 후보 게이트 결과

상태: **오프라인 구현·72문항 개발셋 검증 완료, holdout·운영 통합 보류**. D의 판단을 절대 변경하지 않고 D와 E가 모두 `needs_correction`일 때만 교정문 후보를 비교한다. 선택 과정은 평가셋 정답을 읽지 않는다.

## 설계 원칙

1. D의 `acceptable`·`insufficient_evidence`·`needs_correction` 판단을 그대로 유지한다.
2. 둘 중 하나라도 유효하지 않거나 E가 교정을 제안하지 않으면 D 교정문을 유지한다.
3. 두 모델이 모두 교정을 제안한 경우 다음 순서로 후보를 비교한다.
   - `ください` 요청 의도 보존
   - 원문 정중 종결 보존
   - `いくて`, `いかった`, `いな+명사`, `るます`, `なです` 등 명백한 활용 오류 잔존 개수
   - 위 조건이 같으면 원문 변경량이 작은 후보
4. 모든 점수가 같으면 D를 유지한다.

이 규칙은 문법을 새로 생성하거나 D의 판단을 뒤집지 않는다. 규칙 목록 밖의 오류는 탐지하지 못하며 의미 보존을 완전히 증명하지도 않는다.

## 개발셋 결과

| 지표 | D | E | D 판단 + 후보 게이트 |
| --- | ---: | ---: | ---: |
| JSON/계약 | 72/72 | 72/72 | 72/72 |
| 판단 정확도 | 69/72 | 66/72 | 69/72 |
| 과교정 | 0/33 | 1/33 | 0/33 |
| 교정 탐지 정밀도 | 26/26 | 26/27 | 26/26 |
| 교정 탐지 재현율 | 26/27 | 26/27 | 26/27 |
| 허용 교정문 | 19/27 | 20/27 | **22/27** |
| 복합 오류 완전 탐지 | 0/4 | 1/4 | **1/4** |
| 올바른 보류 | 11/12 | 10/12 | 11/12 |

후보 게이트는 D의 판단 지표를 모두 보존하면서 허용 교정문을 3건 늘렸다. E를 선택한 문항은 JG-040·046·048뿐이며 모두 사전에 회귀 대상으로 지정했던 문항이다.

조건부 운영을 가정해 D가 `needs_correction`인 26문항에서만 E 지연시간을 합산했다. 개발셋 p95는 D 단독 `1006.563ms`, 조건부 게이트 `1942.953ms`로 5초 이내이며 D의 2배 이내다. 이 값은 이미 실행한 두 결과의 요청 지연시간을 합성한 것으로 동시 사용자 부하 시험은 아니다.

- JG-040: 정중체를 버린 D 후보 대신 `弟は漢字を読めます。` 선택
- JG-046: 남은 `安いくて`와 문체 변경이 없는 완전 교정 선택
- JG-048: `小さいな`가 남은 D 후보 대신 두 오류를 모두 고친 후보 선택
- JG-031의 요청→제안 변경과 JG-045의 정중체→보통체 변경은 게이트가 거절했다.

개발셋 자동 안전 목표는 통과하지만 반복 사용한 72문항 결과이므로 일반화 성능이나 운영 승인을 뜻하지 않는다. 두 모델을 모두 실행해야 하므로 추론 비용·지연도 증가한다.
