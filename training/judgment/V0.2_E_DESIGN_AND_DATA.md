# 판단모델 v0.2-E 교정문 회귀 보강 설계·데이터 결과

상태: **설계·결정론적 생성·자동 검증·45-step 학습·72문항 개발셋 비교 완료, 채택 기준 미달**. v0.2-D의 개발셋 회귀만 보강했으며 미사용 `holdout_v0.2` 120문항에는 모델 추론을 실행하지 않았다. 결과는 [v0.2-E 학습·비교](V0.2_E_TRAIN_AND_DEV72_RESULT.md)를 따른다.

## 목적과 채택 조건

v0.2-D는 판단 정확도 69/72, 과교정 0/33으로 개선됐지만 허용 교정문 19/27, 복합 오류 완전 탐지 0/4로 v0.2-C보다 후퇴했다. v0.2-E는 다음 경계를 학습한다.

- 가능 동사의 `読めるます→読めます`처럼 원문의 정중체를 유지한다.
- `安いくて→安くて`, `小さいな→小さい`처럼 잘못된 부분만 고친다.
- 복합 오류는 일부만 고치지 않고 모든 오류를 최소 수정한다.
- `今、何してる？` 계열의 완결된 구어체 의문문을 문맥 부족으로 보류하지 않는다.
- 존재 장소의 `で→に`와 일본어가 아닌 입력의 판단 보류를 유지한다.

개발셋 채택 기준은 JSON/계약 100%, 과교정 0/33 유지, 판단 69/72 이상, 허용 교정문 20/27 이상, 복합 오류 1/4 이상이다. JG-040·046·048은 모두 최소 교정에 성공해야 하며 JG-010·027·060 중 적어도 2건을 개선해야 한다. 이 기준을 충족해도 새 holdout 통과 전에는 운영 후보가 아니다.

추가분에는 정상/오류 최소대립쌍 16개가 있으며 각 쌍은 같은 split에 둔다. 모든 문항은 `generated_validated`이고 사람 또는 일본어 전문가 검수본으로 표시하지 않는다. 기존 v0.2-D 748문항은 레코드 단위로 변경하지 않고 접두부로 보존한다.

## 격리·자동 검증

- 기존 72문항 개발셋, 이전 150문항 holdout, 새 120문항 holdout, v0.2-D 748문항, RAG JSON과 정규화 정확 중복: 0건
- 기존 데이터셋과 문자 3-gram Jaccard 0.85 이상 근접 중복: 0건; 관측 최대 0.6667
- 위치 없는 `judgment-v0.2` ChatML의 네 필드와 canonical 정답 일치 확인
- 교정 문항은 원문과 교정문이 다르고, 허용·보류 문항은 원문을 그대로 유지하도록 검사
- 재생성 결정성과 두 holdout의 SHA-256 불변성을 테스트

중복 검사는 의미상 중복, 사전학습 중복 또는 언어학적 정답성을 보장하지 않는다. holdout은 입력 중복 감사에만 읽고 정답이나 모델 출력을 데이터 생성에 사용하지 않는다.
