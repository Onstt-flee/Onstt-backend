# 판단모델 v0.2-F 보강 설계

상태: **설계 단계, 학습 미실행**. `holdout_v0.2`에서 v0.2-D가 과교정 2/50으로 안전 기준을 실패했으므로 운영 API 통합을 중단한다. 해당 시험지는 다시 모델 선택이나 최종 성능 증명에 사용하지 않는다.

## 확인된 실패 범위

- 정상 보통체 시제를 임의 변경: `今日は少し早く寝る。`를 과거형으로 바꿈
- 이동 경로 표현을 다른 서술어로 치환: `湖の周りを一周走りました。`를 `一周しました`로 바꿈
- `難しいかった`, `安いかった` 등 い형용사 과거 활용 오류 누락
- `掃くます` 등 1그룹 동사 ます형 접속 오류 누락
- 외국어·불완전 발화를 `acceptable`로 처리해 올바른 보류가 15/20에 그침
- 복합 오류 완전 교정 0/10
- JSON 계약 실패 1/120

`corrected_text`가 정확해도 diff 구간이 정답 작성 시의 넓은 구간과 다를 수 있으므로 exact edit 0%를 언어 교정 실패로 해석하지 않는다. 운영에서는 백엔드가 최소 diff를 계산하고 `classification_review_required`를 별도로 기록한다.

## 데이터 보강 원칙

1. 정상/오류 최소대립쌍을 같은 split에 둔다.
2. 보통체·정중체와 현재/과거 시제를 원문 문맥 그대로 보존한다.
3. 이동 경로 `を`와 목적지 `に/へ`를 동사 의미와 함께 대조한다.
4. 다양한 い형용사의 `かった`/`いかった`, 1그룹 동사의 ます형을 보강한다.
5. 외국어·불완전·잡음 입력은 번역하거나 완성하지 않고 `insufficient_evidence`로 둔다.
6. 복합 오류는 조사와 활용을 모두 고친 정답만 허용한다.
7. v0.2 holdout 원문·교정문은 학습 데이터로 복사하거나 변형하지 않는다.
8. 추가 데이터는 `generated_validated`로만 기록하며 사람·전문가 검수로 표시하지 않는다.

## 다음 실행 순서

1. 신규 `holdout_v0.3`을 생성·누수 검사하고 SHA-256으로 먼저 봉인한다.
2. 위 실패 유형의 별도 v0.2-F 학습 데이터를 생성한다.
3. Qwen3-4B·seed 42·45-step의 비교 조건을 유지해 새 어댑터에 학습한다.
4. 기존 72문항은 회귀 진단에만 사용한다.
5. 데이터·프롬프트·어댑터·채점 기준을 다시 고정한 뒤에만 v0.3을 한 번 실행한다.

SudachiPy/ChromaDB 관문은 아직 추가하지 않는다. v0.2-F 이후에도 같은 조사·활용 오류가 반복될 때 해당 유형에 한해 별도 대조 실험한다.
