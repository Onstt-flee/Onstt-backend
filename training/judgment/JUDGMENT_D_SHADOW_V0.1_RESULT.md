# v0.2-D 실제 STT 50건 shadow 결과

## 결론

- 실행일: `2026-10-01` (UTC)
- 전략: `Qwen3-4B + judgment-v0.2-D LoRA` 단독
- 상태: **shadow 실행 완료, 운영 기본값 승격 보류**
- 핵심 사유: JSON/출력 계약 성공률이 `49/50 = 98%`로 사전 기준 `99% 이상`을 충족하지 못했다.
- 공식 50건은 결과 확인 후 재실행하거나 수정하지 않았다. 이 표본은 이후 모델 선택의 새 미사용 시험지로 재사용하지 않는다.

이번 실행은 실제 저장 발화에서 런타임 안정성과 지연시간을 확인한 운영 shadow다. 정답 라벨과 음성 근거가 없으므로 문법 정확도, 과교정률, 발음 오류 또는 STT 오류를 평가한 결과가 아니다.

| 항목 | 값 |

실행 명령은 저장소 루트에서 모듈 형식으로 사용한다.

```bash
venv/bin/python -m scripts.run_judgment_shadow --limit 50
```

원문과 모델 출력이 들어 있는 원시 JSONL은 개인정보 가능성이 있어 Git 제외 경로에만 보관한다. Git에는 집계 결과와 해시만 남긴다.

### 실패 1건 진단

실패 응답은 `decision=insufficient_evidence`였지만 `corrected_text`에서 원문의 일부를 삭제했다. 출력 계약은 `acceptable`과 `insufficient_evidence`가 원문을 그대로 보존하도록 요구하므로 서비스가 `Non-correction decisions must preserve input text`로 거부했다.

- 시스템이 계약 위반을 정상 판단으로 저장하지 않은 것은 의도한 안전 동작이다.
- 그러나 모델의 구조 성공률은 98%이므로 운영 승격 조건에는 실패했다.
- `corrected_text`를 백엔드에서 몰래 원문으로 덮어쓰면 모델 오류가 숨겨지므로 현재는 503 실패를 유지한다.
- 진단 재호출은 실패 형태 확인에만 사용했고 공식 50건 집계나 결과 파일을 바꾸지 않았다.
- 향후 shadow 실행에서는 계약 실패의 원시 모델 출력도 Git 제외 원시 파일에 보존하도록 실행기를 보강했다. 기존 공식 실행 파일은 사후 변조하지 않았다.

## 해석 한계와 다음 결정

1. 최근 50건 표본은 두 STT 모델에만 편중되어 전체 운영 분포를 대표한다고 단정할 수 없다.
2. 정답 라벨이 없으므로 판단 정확도·과교정률·재현율을 계산하지 않는다.
3. 오디오를 대조하지 않았으므로 표기 문제를 학습자 발음 오류나 STT 오류로 귀속하지 않는다.
4. 현재 기능 플래그 기본값 `JUDGMENT_ENABLED=false`와 D 단독 설정을 유지한다.
5. 비교 가능한 새 shadow 표본을 실행하기 전, 비교정 판단의 원문 보존 실패를 프롬프트·학습 데이터·계약 감사 관점에서 수정하고 전체 회귀 검증을 통과해야 한다.
6. 실제 품질 승격에는 별도의 동의된 표본과 독립 라벨 검수가 필요하다. 이 자동 shadow만으로 학습자 노출을 승인하지 않는다.
