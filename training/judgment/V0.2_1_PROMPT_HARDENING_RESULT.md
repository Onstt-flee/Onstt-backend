# judgment-v0.2.1 원문 보존 프롬프트 강화 실험

## 결론

- 실험일: `2026-10-03`
- 대상: 동일한 `Qwen3-4B + judgment-v0.2-D LoRA`
- 비교: 기존 `judgment-v0.2` 대조군과 원문 복사 규칙을 강화한 `judgment-v0.2.1`
- 데이터: 반복 사용 가능한 72문항 개발셋
- 결정: **v0.2.1 프롬프트 미채택**

v0.2.1은 실제 STT shadow에서 발견한 “비교정 판단이 원문 일부를 삭제”하는 문제를 프롬프트만으로 줄일 수 있는지 확인한 실험이다. 같은 서버에서 두 프롬프트를 각각 전체 실행했지만 구조 계약, 판단 정확도, 교정 재현율과 허용 교정문이 모두 후퇴했다. 운영 API는 계속 v0.2를 사용하며 기능 플래그 기본 비활성을 유지한다.

## 변경 내용

기존 v0.2 계약의 네 출력 필드는 바꾸지 않았다.

- `acceptable`과 `insufficient_evidence`에서는 입력 JSON의 `text`를 문자 단위로 정확히 복사하도록 명시
- 공백·구두점·표기·불완전한 부분의 삭제·추가·완성·정규화·번역 금지
- 출력 직전 비교정 판단의 `corrected_text == text` 재확인 지시
- 자동 덮어쓰기, 파서 수리, 판단 변경은 추가하지 않음

소비된 holdout 규약이 `evaluation/judgment/runner.py`의 SHA-256을 고정하고 있으므로 이 파일은 기존 해시 `0884093a3f7dd9341bb7e0c4d43956bda5d11e735d036c0bfd000569197d8a46`로 복원했다. v0.2.1 프롬프트와 재현 진입점은 `evaluation/judgment/prompt_v021.py`에 격리했다. 운영 `analyzer/judgment_service.py`는 이번 실험 후에도 `PROMPT_VERSION_V2`를 사용한다.

재현할 때만 다음 별도 모듈을 사용한다.

```bash
venv/bin/python -B -m evaluation.judgment.prompt_v021 \
  --dataset evaluation/judgment/seed_v0.1.jsonl \
  --model judgment-v02d \
  --prompt-version judgment-v0.2.1 \
  --output evaluation/judgment/runs/v021-reproduction.jsonl
```

## 동일 조건

| 항목 | 값 |
| --- | --- |
| 베이스 | `Qwen/Qwen3-4B-Instruct-2507` BF16 |
| LoRA | `judgment-qwen3-4b-failure-focus-v0.2-d` |
| 데이터 | `evaluation/judgment/seed_v0.1.jsonl`, 72문항 |
| temperature / top_p | `0.0 / 1.0` |
| max tokens | `512` |
| 서버 | vLLM 0.28.0, 같은 프로세스 |
| sampling | FlashInfer sampler CUDA/CUB 호환 오류로 `VLLM_USE_FLASHINFER_SAMPLER=0` |

첫 서버 기동은 FlashInfer sampling 커널 JIT가 현재 CUDA/CUB 조합에서 컴파일되지 않아 추론 전에 실패했다. 모델·가중치 문제가 아니며, vLLM이 제공하는 환경 설정으로 sampler만 비활성화한 뒤 두 프롬프트를 같은 조건에서 순차 실행했다.

두 실행 모두 99% 구조 기준을 통과하지 못했다. v0.2 대조군의 1건 실패는 장문 반복으로 512-token 제한에서 JSON 문자열이 닫히지 않은 사례다. v0.2.1 실패 3건은 무변경 `needs_correction` 2건과 비교정 원문 불일치 1건이다. 강화 지시가 실제 shadow 실패 유형을 제거하지 못했다.

72문항은 이미 반복 사용한 개발셋이므로 이 결과는 프롬프트 회귀 판정에만 사용하며 새로운 운영 성능 증명이 아니다.

## 다음 결정

1. v0.2.1을 운영 API나 새 shadow에 사용하지 않는다.
2. 비교정 판단의 원문 보존 실패는 프롬프트만 늘리는 방식으로 해결하지 않는다.
3. 실제 원문은 학습에 사용하지 않고, 같은 실패 구조를 가진 합성 최소대립 예시를 v0.2-G 후보 데이터로 만든다.
4. 비교정 원문 보존, 무변경 교정 금지, 짧은 구어체 허용, 미완성·잡음 표기 보존을 집중 보강한다.
5. v0.2-G를 기존 D와 같은 베이스·seed·step 조건으로 비교한 뒤에만 새 미사용 shadow 표본을 설계한다.
