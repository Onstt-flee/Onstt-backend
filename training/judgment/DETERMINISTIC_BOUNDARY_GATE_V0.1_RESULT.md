# 결정론적 판단 경계 게이트 v0.1 설계·개발셋 replay 결과

상태: **독립 오프라인 구현·개발셋 replay 완료, 운영 API 미통합**. 빈 입력·잡음·명백한 비일본어를 모델 밖에서 처리하고, STT 표기 후보는 문법 교정과 분리된 advisory로만 보존한다. 평가 ID·정답 라벨·holdout은 라우팅에 사용하지 않는다.

## 목적과 책임 경계

모델이 반복적으로 실패한 경계는 문법 추론과 다른 문제다.

1. 빈 입력·잡음은 교정할 문장이 없다.
2. 일본어 증거가 전혀 없는 영어·한국어 문장은 번역 대상일 수 있지만 일본어 문법 교정 대상은 아니다.
3. `わ/は`, `お/を` 같은 STT 표기는 원음 없이 학습자 발음과 전사 오류 중 어느 쪽인지 확정할 수 없다.

따라서 게이트는 다음 원칙을 따른다.

- 증거가 명확한 경계만 모델 호출 전에 `insufficient_evidence`로 종료한다.
- 원문은 한 글자도 바꾸지 않는다.
- 한자만 있는 입력, 일본어와 외국어가 섞인 입력 등 모호한 사례는 모델로 넘긴다.
- STT 표기 후보는 문법 판단과 별도 advisory로 기록한다.
- 모델의 교정문이 정확히 하나의 표기 후보와 같고 오류 유형도 조사 하나일 때만 문법 교정을 원문 유지로 분리할 수 있다.
- 더 넓은 수정, 시제·활용 수정, 후보와 정확히 일치하지 않는 수정은 절대 덮어쓰지 않는다.

### 사전 라우팅

| 입력 유형 | 처리 |
| --- | --- |
| 빈 문자열·공백 | 모델 호출 없이 보류, 원문 보존 |
| 구두점만 있는 입력 | 모델 호출 없이 보류, 원문 보존 |
| `[雑音]`, `[noise]` 등 잡음만 있는 입력 | 모델 호출 없이 보류, 원문 보존 |
| 일본어 문자 증거가 없고 라틴·한글 문자가 있는 입력 | 모델 호출 없이 범위 밖 보류 |
| 한자만 있는 입력 | 언어 귀속이 모호하므로 모델 호출 |
| 일본어+외국어 혼합 | 모델 호출 |
| 필러 뒤에 내용이 있는 일본어 | 모델 호출 |

### STT 표기 advisory

STT·전사·원음 문맥이 명시된 경우에만 매우 제한된 패턴을 후보로 만든다.

- `わたしわ…` → `わたしは…`
- 한자 명사+`お`+제한된 동사 ます 어간 → 조사 `を` 후보

advisory에는 위치, 원문, 후보 표기, `attribution=unknown`, `action=advisory_only`를 기록한다. `本をお読みになります。` 같은 정상 경어 표현은 후보로 잡지 않는다.

## D/H 개발셋 replay

기존 검증된 원시 run에 정책을 재생했으며 모델을 다시 호출하지 않았다. replay는 개발 진단으로만 사용한다.

| 지표 | D 원본 | D+경계 v0.1 | H 원본 | H+경계 v0.1 |
| --- | ---: | ---: | ---: | ---: |
| 구조 계약 | 72/72 | 72/72 | 71/72 | 72/72 |
| 판단 정확도 | 69/72 | 70/72 | 68/72 | 70/72 |
| 과교정 | 0/33 | 0/33 | 1/33 | 1/33 |
| 올바른 보류 | 11/12 | 12/12 | 10/12 | 12/12 |
| 허용 교정문 | 19/27 | 19/27 | 19/27 | 19/27 |

두 run 모두 5건(`JG-049`, `050`, `057`, `059`, `060`)을 사전 라우팅할 수 있었다. D에서는 한국어 입력 `JG-060`이 회복됐다. H에서는 빈 입력 구조 실패와 비일본어 보류가 회복됐다.

`JG-067`·`068`은 advisory로 탐지했다. 그러나 H의 `JG-068` 교정문은 후보 `本を読みます。`가 아니라 `本をお読みます。`였으므로 정확 일치 안전 규칙이 덮어쓰지 않았다. 그 결과 H의 과교정 1/33은 그대로 남았다. 이는 정책이 평가 점수를 맞추기 위해 광범위하게 모델 출력을 무효화하지 않는다는 안전 근거다.

## 판정

1. D+경계 v0.1은 개발셋에서 D의 과교정·교정문 성능을 유지하면서 보류를 12/12로 높였다.
2. H+경계 v0.1은 구조와 보류가 개선됐지만 과교정 기준을 계속 실패한다.
3. H는 여전히 v0.4 실행 후보가 아니다.
4. D를 모델 기준선으로 유지한다.
5. 경계 정책은 유망하지만 반복 사용한 개발셋 replay이므로 운영 승격 근거가 아니다.
6. 현재 운영 API에는 연결하지 않는다.

## 다음 단계

1. 규칙 전용의 평가 ID·정답 비의존 adversarial 사례를 더 추가해 오탐 방지 범위를 넓힌다.
2. 실제 STT shadow 원문에 대해 텍스트를 저장하거나 DB를 변경하지 않는 dry-run으로 라우팅 비율과 후보 수만 집계한다.
3. 과도한 bypass가 없고 기존 일본어 입력이 모델로 유지되는지 확인한다.
4. 그 결과가 안전하면 별도 기능 플래그 아래 사전 라우팅만 운영 서비스에 연결한다.
5. STT advisory는 응답·DB 계약 확장이 필요하므로 사전 라우팅과 분리해 나중에 통합한다.
6. 새 후보·정책·임계값을 체크포인트로 고정하기 전에는 `holdout_v0.4`를 실행하지 않는다.

## 2026-10-06 실제 저장 STT 집계 dry-run

운영 SQLite를 읽기 전용으로 열고 적격 `language=ja` 발화 전체에 정책을 적용했다. 모델 호출, 개별 결과 파일, DB 저장은 수행하지 않았다.

| 항목 | 결과 |

| 전체 utterance | 342 |
| 적격 입력 | 340 |
| 모델 경로 유지 | 340 |
| 결정론적 bypass | 0 |
| STT 표기 advisory 행 | 0 |

입력은 모두 `stt_text`였고 연결 사용자 수준은 모두 N5 기본값이었다. STT 모델 분포는 `whisper-tiny-lowskilled` 150, `whisper-tiny-tts` 150, `faster-whisper-tiny-tuned` 29, `faster-whisper-small` 9, `faster-whisper-tiny` 2건이다.

DB SHA-256은 실행 전후 모두 `ef3b42b92516c5332f2ed1dcd63ffe1a9c2ff8a53650c24a32205a0161ff09c9`로 같고 `judgment_results`는 0건으로 유지됐다. 집계 결과에는 원문, 발화 ID, 사용자 식별자, 행별 결과가 없다.

이 결과는 현재 저장 표본에서 규칙이 일본어 입력을 잘못 가로채지 않았다는 제한적인 안전 신호다. 반대로 bypass와 advisory가 모두 0건이므로 현재 데이터 분포에서는 지연시간·비용 절감이나 품질 개선 효과도 관측되지 않았다. 골드 라벨과 음성 대조가 없으므로 문법 정확도나 오탐률을 계산할 수 없다.
